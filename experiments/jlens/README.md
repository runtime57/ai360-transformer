# J-lens на TinyStories GPT

J-lens (Jacobian lens): `J_l = E[∂h_final,t' / ∂h_l,t]` по `t' ≥ t`, чтение `softmax(W_U · LN_final(J_l h_l))`.
Logit lens — частный случай `J_l = I`.

```bash
# распаковать src/saved/tinystory_model(1).zip в DIR
python fit.py --ckpt DIR/saved/tinystory_gpt/model_best.pth --vocab DIR/data/tokenizer/bpe/tinystory.json --out J.pt   # ~1 ч на CPU
python run_experiments.py --ckpt ... --vocab ... --J J.pt   # -> figures/*.png, figures/results.json
```

`core.py` содержит собственный byte-level BPE (без пакета `tokenizers`), загрузку модели и оценку J.
J оценён на 48 окнах по 64 токена из val.txt (строки 0–1199); эксперименты считаются на отложенных строках 1200+.

## Эксперимент 6 · Видит ли J-lens будущее лучше logit lens?

Exp4 (top-10 для x[t+2], x[t+3]) преимущества J-lens не показал. Exp6 ставит вопрос строже и добавляет абляцию механизма.

**План, зафиксированный до запуска**

- *Данные:* 300 историй из TinyStories validation, которых нет в `val.txt` (их не видели ни при обучении модели, ни при оценке `J.pt`), по формату обучения: `<bos>` + история, ≤128 токенов.
- *Что считается «будущим»:* только **новые** токены x[t+d]. Их нет в контексте x[0..t], и при d≥2 они не совпадают со следующим токеном. Так копирование из контекста и обычное next-token предсказание не могут объяснить выигрыш.
- *Метрика (ранговая, от температуры линзы не зависит):* перцентиль токена среди «негативов», то есть словаря без контекста и без всех токенов, которые ещё встретятся в истории. **Future-window AUC** — это средний перцентиль различных новых токенов из x[t+2..t+16].
- **Основной критерий (H1):** ΔAUC(J-lens из `J.pt` − logit lens) на слоях emb…L5, 95% парный бутстреп-CI по историям. H1 подтверждается на слое, если CI > 0.
- *Вторичные метрики:* профиль по расстоянию d=1..32; «дальнее окно» (токены, впервые появляющиеся только через 8..32 позиций); бейзлайн по униграммной частоте.
- **H2 (механизм):** J оценён по расстояниям (`fit_by_distance.py`, train-сплит). `J_same` = E[∂h_L,t/∂h_l,t] (без усреднения по будущему), `J_fut` = E[∂h_L,t'/∂h_l,t], t'>t. Если преимущество J-lens действительно берётся из усреднения по будущим позициям, то `J_fut` > `J_same` на будущих токенах.
- *Добавлено после smoke-теста на 12 историях (до основного запуска):* униграммная частота сама даёт AUC≈0.89, выше всех линз и даже выхода модели. Поэтому к основному критерию добавлен контроль **freq-matched**: токен сравнивается только с негативами из того же частотного бина (50 бинов).

```bash
python fit_by_distance.py --ckpt ... --vocab ... --out J_dist.pt --batches 60   # ~70 мин на CPU, 103 МБ (в .gitignore)
python exp6_future.py --ckpt ... --vocab ... --J J.pt --Jdist J_dist.pt   # -> figures/exp6_*.png, exp6_results.json
```

**Результаты** (`figures/exp6_future_auc.png`, `figures/exp6_future_distance.png`, `figures/exp6_results.json`; 300 историй, 35 334 позиции; `J_dist.pt` — 60 батчей = 240 выборок якобиана, split-half cos ≥ 0.989, cos(перефит J_all, `J.pt`) ≥ 0.986)

ΔAUC(W=16) относительно logit lens, в скобках 95% CI:

| слой | J-lens, сырой AUC (основной критерий) | J-lens, freq-matched | J_same, freq-matched | J_fut, freq-matched |
|---|---|---|---|---|
| emb | **+0.062** [+0.060, +0.064] | **+0.024** | −0.006 | +0.023 |
| L1 | **+0.019** [+0.017, +0.021] | **+0.021** | −0.008 | +0.015 |
| L2 | **+0.003** [+0.002, +0.005] | **+0.027** | −0.007 | +0.009 |
| L3 | −0.013 [−0.015, −0.012] | **+0.023** | −0.008 | +0.001 (н/з) |
| L4 | −0.038 [−0.039, −0.037] | **+0.019** | −0.011 | −0.001 (н/з) |
| L5 | −0.034 [−0.035, −0.033] | **+0.010** | −0.008 | −0.026 |

1. **H1 по основному критерию подтверждена только частично.** На сыром AUC J-lens лучше на emb–L2, а на L3–L5 logit lens его обходит.
2. **Причина — частотный приор, а не знание будущего.** Ранговая корреляция скоров с униграммной частотой у logit lens на L3–L5 составляет ρ≈0.53–0.55 (выше, чем у выхода модели, 0.53), у J-lens ρ≈0.41–0.45. Частотные токены чаще встречаются в будущем, и сырой AUC за это вознаграждает (униграмма в одиночку даёт 0.897, больше любой линзы). Если сравнивать только с негативами той же частоты, **J-lens лучше logit lens на каждом слое**. В дальнем окне (токены, которые впервые появляются через 8–32 позиций) он тоже лучше на каждом слое (+0.005…+0.016).
3. **H2 подтверждена: преимущество берётся именно из усреднения по будущим позициям.** `J_same` (тот же линейный перевод, но без t'>t) на freq-matched *хуже* logit lens на всех слоях. `J_fut` лучше `J_same` на emb–L4 (+0.009…+0.029; в дальнем окне +0.016…+0.022). Значит, J-lens выигрывает не потому, что он «лучше переводит» residual в словарь, а потому, что кодирует влияние на будущие позиции. Лучше всех полный J-lens: это смесь «следующего токена» (d=0) и «будущего» (d≥1).
4. **Где виден эффект:** в основном ближнее будущее, d≈2–8 (exp6b). К d≈32 кривые сходятся. На следующем токене (d=1) J-lens на поздних слоях хуже logit lens, что согласуется с exp1.
5. **По сравнению с выходом модели:** freq-matched J-lens на L5 немного обходит финальное распределение (+0.006 [+0.004, +0.007]), на L4 идёт вровень. Предсказание будущего на этих слоях содержательнее, чем в next-token выходе, но эффект маленький.

*Ограничения:* CI учитывают только выборку историй, а не шум оценки J. Это частично закрывается split-half ≥0.989 и тем, что с J по 10 батчам выводы совпали. Модель одна, маленькая (6 слоёв, d=512), корпус один (TinyStories). `J_fut` на L5 опирается только на внимание последнего блока и работает плохо. На L6 `J_fut` по определению равен 0, поэтому там подставлено I.
